# Data Fetching

The app uses server-rendered reads by default and small client effects only where the UI needs live search or status updates. It does not currently use TanStack Query or SWR; the cart context in `src/app/providers.jsx` is unrelated to server data.

| Read                                  | Location                                                                                                      | Logical key                                              | Refresh / cache rule                                                                                       | Reason                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Restaurant details and home specials  | `src/app/page.js`: `getRestaurantInfo()` and `getDishes()`                                                    | Restaurant; dish catalog IDs                             | Server page revalidates every 3,600 seconds                                                                | Render the hero and Today's Specials in the initial HTML                           |
| Initial menu and URL-filtered results | `src/app/menu/page.js`: `getDishesByCategory(category, query)`                                                | `category` and `q` URL parameters                        | Server-rendered for each search-param request; route declares 3,600-second revalidation. No client polling | Make categories/search shareable and return meaningful HTML before hydration       |
| Live menu search                      | `src/app/menu/SearchBox.jsx` calls `GET /api/dishes?category=…&q=…`; handler in `src/app/api/dishes/route.js` | Request URL (`category`, `q`); no shared query-cache key | Wait 300 ms after input; abort the previous request; no periodic refresh                                   | Avoid a request per keystroke while keeping results responsive                     |
| Dish detail                           | `src/app/menu/[id]/page.js`: `getDish(id)`                                                                    | Dish `id` in the path                                    | Generated by `generateStaticParams`; refreshed by a new build/deployment                                   | Statically render catalog pages and metadata for each real dish                    |
| Dish detail API                       | `src/app/api/dishes/[id]/route.js`: `getDish(id)`                                                             | Dish `id` in the path                                    | Read from the in-memory catalog on each request; no client polling                                         | Provide a single-dish JSON endpoint                                                |
| Customer order history                | `src/app/orders/page.js`: `getOrders(user.id)`                                                                | Authenticated session user ID                            | Dynamic server read on each page request; not shared or publicly cached                                    | Keep history scoped to the signed-in customer and include initial statuses in HTML |
| Order status                          | Initially supplied by `OrdersPage`; `src/app/orders/OrderStatus.jsx` polls `GET /api/orders/[id]`             | Order `id` in the path; API verifies session ownership   | Poll every 10 seconds while pending/confirmed/preparing; stop after delivered/cancelled                    | Show server-rendered status immediately, then keep active orders current           |
| Orders API list                       | `src/app/api/orders/route.js`: `getOrders(user.id)`                                                           | Authenticated session user ID                            | Read on each authenticated request; no periodic client refresh from this endpoint                          | Expose only the current customer's orders                                          |
| Order API detail                      | `src/app/api/orders/[id]/route.js`: `getOrder(id)` plus owner check                                           | Order `id` and authenticated session user ID             | Read on each authenticated request; no shared cache                                                        | Support status polling without allowing cross-user reads                           |
| Staff kitchen/admin order lists       | `src/app/kitchen/page.js` and `src/app/admin/page.js`: `getAllOrders()`                                       | All orders; staff session required                       | Dynamic server read on each page request                                                                   | Give staff the live in-memory queue and reporting data                             |

## Storage notes

The dish catalog is static module data in `src/lib/dishes.js`. Orders are held in process memory in `src/lib/orders.js`, so they disappear on restart and are not suitable for a multi-instance production deployment. The cart is React context state in `src/app/providers.jsx`; it survives client navigation while mounted but is not persisted across reloads.
